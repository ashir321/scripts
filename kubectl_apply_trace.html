01
Client preflight
kubectl
Parse manifest, resolve auth, build server-side patch
  • Load ~/.kube/config → current-context user/cluster
  • Resolve credential plugin (x509 / exec / oidc / sa-token)
  • Discovery: GET /api, /apis → cached locally
  • Map kind: Deployment → apps/v1/deployments
  • Compute strategic merge patch vs last-applied-configuration

02
TLS handshake → API server
network
mTLS to kube-apiserver on :6443
  • Verify server cert chain against cluster CA
  • Present client cert / bearer token / SA JWT
  • HTTP/2 stream multiplexing established
  • Request: PATCH /apis/apps/v1/namespaces/prod/deployments/api-svc
est. ~ 2–10 ms · network rtt
03
Authentication
apiserver
First authenticator that succeeds wins
  • x509 → CN = user, O = group(s)
  • ServiceAccount JWT → projected, bound, audience-scoped
  • OIDC id_token → issuer + signature verification
  • Webhook TokenReview (e.g. aws-iam-authenticator)
  • Output: user.Info{name, uid, groups, extra}
est. ~ 1–5 ms · in-proc
04
Authorization
RBAC + Node
Verb × resource × namespace against bindings
  • Authorizer chain: Node → RBAC → Webhook
  • Match (user, groups) × (patch, deployments, prod)
  • First explicit allow wins; default deny
  • Reject → 403 Forbidden, no further processing
est. ~ 0.5–3 ms · in-proc
05
Mutating admission
in-tree + webhooks
Object is rewritten — defaults, sidecars, labels
  • In-tree: ServiceAccount, DefaultStorageClass, LimitRanger, Priority
  • External: MutatingWebhookConfiguration → AdmissionReview v1
  • Examples: Istio sidecar inject, vault-agent, image-tag pinning
  • Runs serially — each sees prior mutation
  • failurePolicy: Fail + dead webhook = full outage
est. ~ 5–80 ms · per webhook hop
06
Schema validation
apiserver
Structural check against OpenAPI / CRD schema
  • Built-in types: compiled OpenAPI v3 schema
  • CRDs: spec.versions[].schema.openAPIV3Schema
  • Unknown fields → reject in --strict mode
  • Type coercion, required fields, enum constraints
est. ~ 1–5 ms · in-proc
07
Validating admission
webhooks + CEL
Last gate — accept or reject. No mutation allowed.
  • In-tree: ResourceQuota, PodSecurity, CertificateSubjectRestriction
  • ValidatingWebhookConfiguration — Kyverno, OPA Gatekeeper
  • ValidatingAdmissionPolicy (GA 1.30) — in-process CEL, no webhook hop
  • Runs in parallel; any reject fails the request
est. ~ 3–50 ms · per webhook
08
Persist to etcd
etcd quorum
Encoded, encrypted at rest, replicated via Raft
  • Serialize: protobuf (built-ins) / JSON (some CRDs)
  • Encrypt: KMS / aescbc / aesgcm if EncryptionConfiguration set
  • Key: /registry/deployments/prod/api-svc
  • Server assigns resourceVersion = etcd ModRevision
  • Raft quorum write across etcd peers
est. ~ 5–25 ms · disk + quorum
09
Response to client
apiserver
200 OK with persisted object — apply is "done"
  • Return body = object as committed (post-mutation)
  • kubectl prints deployment.apps/api-svc configured
  • Nothing is running yet — only state is recorded
  • Watch events fire to all interested controllers
est. ~ < 1 ms · response
phase ii — async reconciliation
watch-driven, level-triggered
10
Deployment controller
kube-controller-mgr
Watch fires → reconcile loop creates a ReplicaSet
  • Informer cache hit → enqueue work item
  • Diff current vs desired replicas
  • Strategy: RollingUpdate with maxSurge / maxUnavailable
  • POST new ReplicaSet with pod-template-hash
est. ~ 50–200 ms · reconcile
11
ReplicaSet controller
kube-controller-mgr
Creates N Pod objects — all phase: Pending, no node
  • Diff spec.replicas vs live pod count for the RS
  • Burst-create pods (parallel POST) with owner refs
  • Pods enter etcd with nodeName: ""
  • Status: Pending / PodScheduled=False
est. ~ 100–300 ms · burst
12
Scheduler
kube-scheduler
Filter → score → reserve → bind
  • Watches pods with empty spec.nodeName
  • Filter plugins: NodeAffinity, TaintToleration, NodeResourcesFit, VolumeBinding, PodTopologySpread
  • Score plugins: rank feasible nodes 0–100
  • Bind subresource: POST .../binding writes nodeName
est. ~ 20–150 ms · per pod
13
kubelet admits pod
kubelet · CRI · CNI · CSI
Sandbox → network → volumes → containers
  • kubelet watches pods where spec.nodeName = self
  • Admit: eviction mgr, topology mgr, device plugins
  • CRI → containerd creates pause sandbox + netns
  • CNI → Calico/Cilium plumbs veth, IP, routes
  • CSI → driver Attach + NodeStage + NodePublish
  • Image pull per imagePullPolicy → init containers → main
est. ~ 0.5–30 s · incl. image pull
14
Probes pass · status reported
kubelet
Pod transitions to Running → Ready → traffic
  • Probes: startup → liveness + readiness loop
  • PATCH pod status.conditions[Ready] = True
  • Endpoint controller adds pod IP to Service EndpointSlice
  • kube-proxy / Cilium programs iptables / IPVS / eBPF rules
  • Traffic now flowing to the new pod
est. ~ 1–60 s · until Ready
two membranes Treat kubectl apply as crossing two distinct boundaries. Membrane 1 is synchronous and gate-keeping: authN → authZ → mutate → schema → validate → etcd. If apply itself fails, the cause lives here — almost always RBAC, a schema mismatch, or a webhook with failurePolicy: Fail hitting an unreachable backend. Membrane 2 is asynchronous, level-triggered, and watch-driven: controllers + scheduler + kubelet drive actual state toward the spec just persisted. If apply returns success but nothing runs, the failure is here — scheduling pressure, image-pull errors, CNI/CSI failures, or runtime quota.
